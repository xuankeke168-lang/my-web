## 一、快捷键速查表：练熟这些，操作如飞

快捷键是提效的第一步——不用鼠标、不用想，手指记忆就完成了操作：

| 快捷键 | 作用 | 使用场景 |
|--------|------|---------|
| `Ctrl + C` | 取消当前输入或生成 | AI正在回复时想打断重来 |
| `Ctrl + D` | 退出Claude Code | 结束会话时 |
| `Ctrl + L` | 清屏 | 屏幕太乱时清一下 |
| `方向键↑/↓` | 浏览历史命令 | 重复之前的提需求 |
| `Tab`（自动补全） | 补全命令或路径 | 输入长路径时 |
| `Esc + Esc`（连按两次） | 打开Rewind回滚菜单 | 想回退到之前的某个步骤 |

**我的练习顺序：**
1. 第1天：`Ctrl + C` 和 `Ctrl + L` 形成肌肉记忆
2. 第3天：方向键浏览历史用熟
3. 第1周：Rewind功能（Esc+Esc）开始频繁使用

## 二、模型选择：不同任务用不同模型，省钱又高效

Claude Code支持多款模型，核心原则是**按任务匹配**，而不是一律用最强的：

### 模型对比

| 模型 | 适合场景 | Token成本 | 回答速度 | 推荐度 |
|------|---------|-----------|---------|-------|
| **Haiku 4.5** | 简单问答、格式化代码、翻译、正则编写 | ❄️ 最低 | ⚡ 最快 | ⭐⭐⭐ |
| **Sonnet 4.6** | 日常开发、代码修改、Bug修复、功能实现 | 💰 中等 | 🚀 快 | ⭐⭐⭐⭐⭐ |
| **Opus 4.5** | 架构设计、复杂调试、性能优化、代码审查 | 🔥 较贵 | 🐢 较慢 | ⭐⭐⭐⭐ |

### 我的默认规则

```
简单任务（查API、写小函数）→ Haiku
日常开发（写功能、改Bug）→ Sonnet（默认）
复杂问题（架构设计、性能调优）→ Opus
```

### 怎么切换？

```bash
# 在交互模式中
/model claude-sonnet-4-6
/model claude-opus-4-5
/model claude-haiku-4-5

# 或者在启动时指定
claude --model claude-opus-4-5
```

**省钱小贴士：** Sonnet 能解决95%的日常问题，只有那5%真正复杂的情况才切Opus。别一上来就用Opus——没必要，而且贵不少。

## 三、Checkpoint & Checkout：放手大胆干，翻车也不怕

这是我最爱的功能，值得单独一大段来讲。

### 问题场景

写代码经常遇到这种情况：

1. 写完登录模块，感觉不错
2. 继续写注册模块，改着改着发现"诶，好像方向不太对"
3. 想回到第1步的状态，但Git已经commit了好几次，reset又怕丢代码

### 解决方案：Checkpoint

```bash
# 完成一个里程碑，打个标记
> /checkpoint 登录模块完成

# 继续往下写...
# 写到一半感觉不对
# 想回到"登录模块完成"那一刻
> /checkout 登录模块完成
✨ 代码和对话上下文都回滚到了那个检查点！
```

### 和Git的区别

| 特性 | Git Commit | Claude Checkpoint |
|------|-----------|-------------------|
| 回滚范围 | 代码文件 | 代码 + 对话上下文 |
| 操作成本 | 需要写commit message | 一句话标记 |
| 回滚精度 | 整个commit | 精确保留状态 |
| 适用场景 | 正式版本管理 | 日常探索式开发 |

### 我的Checkpoint节奏

```
每完成一个逻辑单元就打一个 → 至少每小时打一个
命名要有意义 → "完成了XX功能"，别写"asdf"或"checkpoint1"
做重大改动前先打一个 → 方便反悔
```

## 四、会话管理：用好这些命令，掌控全局

### /status — 查看会话状态

```bash
> /status
```

显示当前会话的概览信息：
- 当前使用的模型
- Token使用量
- 会话时长
- 已创建的检查点列表

### /context — 深度分析

```bash
> /context
```

比`/status`更详细，显示：
- 对话上下文中包含了哪些文件
- 哪些代码被读取过
- 当前AI"记住"了哪些信息

### /compact — 压缩对话

```bash
> /compact
```

**什么时候该执行：**
- AI回答速度明显变慢
- Token用量超过限制的80%
- 对话超过50轮
- 感觉AI开始"遗忘"前面的内容

**工作原理：** AI会分析对话历史，保留关键决策和代码上下文，压缩冗余的讨论内容。整个过程自动完成，不需要你操心。

### /export — 导出重要讨论

```bash
# 导出为Markdown
> /export ~/docs/session-notes.md

# 导出的内容包含：
# - 完整的对话记录
# - 所有代码修改的汇总
# - 创建的检查点列表
```

适合在**完成一个重要任务后**导出，作为技术文档存档。

## 五、Rewind功能：后悔药中的后悔药

`Esc + Esc` 打开的Rewind菜单，比`/undo`更强大——它可以回退多步：

```bash
# 场景：你连续做了3步操作，想回到第1步之后的状态
# 按 Esc + Esc 打开Rewind菜单
# 菜单会列出最近的操作历史
# 选择你想回退到的那一步
# 确认后，代码和上下文一起回滚
```

**和/undo的区别：**
- `/undo`：只撤销上一步
- `Rewind`：可以回退任意多步，可以看到历史操作列表

## 六、日常高效工作流分享

### 上午：快速启动

```bash
# 进入项目
cd ~/projects/my-app

# 启动Claude Code
claude

# 问问今天的任务
> 帮我看看项目中还有哪些TODO没做
> 看看git log，了解一下最近的变更
```

### 工作中：高效推进

```bash
# 明确任务，分步执行
> 今天的主要任务是完成用户评论功能
> 先帮我设计数据库模型

# 完成后打标
> /checkpoint 评论数据模型完成

# 继续下一阶段
> 现在实现评论的CRUD API

# Token差不多了就压缩
> /compact
```

### 遇到问题时

```bash
> 帮我看看这个报错是什么意思
# AI分析错误并给出解决方案

# 如果方案不对，回退重新来
> /undo
> 换个思路，我觉得可能是数据库连接的问题
```

### 下班前

```bash
# 导出今天的讨论记录
> /export ~/docs/worklog-2026-04-25.md

# 打完最后一个检查点
> /checkpoint 评论功能全部完成

# 退出
Ctrl + D
```

## 七、省钱终极指南

Token就是钱，省Token就是省钱：

| 技巧 | 省Token效果 | 操作成本 |
|------|------------|---------|
| 简单任务用Haiku | 节省50-70% | 0（切模型而已） |
| 定期执行/compact | 节省20-40% | 1条命令 |
| 不要一次提太多需求 | 避免无效生成 | 需要习惯 |
| 用`-p`模式处理纯文本 | 省去对话开销 | 看场景使用 |
| 别开Extended Thinking闲聊 | 避免90%额外消耗 | 有意识控制 |

## 八、常见问题

**Q: 模型切换到Opus后，还能切回Sonnet吗？**
A: 当然，`/model claude-sonnet-4-6` 即可切回。注意切换不会清空对话上下文。

**Q: Checkpoint 存在哪里？会占用很多空间吗？**
A: 存在项目目录下的 `.claude/checkpoints/` 里。每个checkpoint只存增量差异，空间占用很小。

**Q: /compact 压缩后会不会丢失重要信息？**
A: AI会智能保留关键上下文。但如果对话中有特别重要的细节，建议先用 `/export` 导出备份再压缩。

## 总结

高效使用Claude Code，关键在于三个习惯：

1. **用对模型** — 简单任务Haiku，日常Sonnet，复杂才Opus
2. **勤打Checkpoint** — 每个逻辑单元完成就打，放手大胆尝试
3. **管好会话** — 定期compact、适时export、用好rewind

这些技巧单个看起来都不难，但组合使用的效果是1+1>2的。
